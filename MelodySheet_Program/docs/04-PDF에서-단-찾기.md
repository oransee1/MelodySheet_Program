# 04. PDF에서 단 찾기

시계가 맞아도 단을 잘못 자르면 커서가 엉뚱한 줄에 선다.

## 무엇을 찾는가

한 **단**은 그 순간 같이 연주하는 모든 악기의 오선 묶음이다.

```text
(잘못)  오선 5줄 = 단 5개     → 커서가 바이올린 줄만 훑거나 피아노 한 손만 가리킴
(맞음)  피아노+바이올린+첼로+베이스 = 단 1개
```

악기와 악기 사이 빈 칸은 좁고, 단과 단 사이 빈 칸은 넓다. 코드는 가로로 잉크가 많은 줄을 모아, 좁은 틈은 붙이고 넓은 틈에서만 가른다. 그 넓은 틈 임계값이 대략 **0.70인치** (`score_layout.py` 의 `merge_gap`).

## 중간 산출물

`analyze_score_layout(...)` 가 주는 것:

- `layout.systems` — 단 목록
- 각 단: `y0, y1` (스티치 이미지 좌표), `page_index`, `start_measure~end_measure`, `bar_xs` (세로줄 x)

페이지 머리글·페이지 번호는 잘라 낸다. 안 자르면 바닥 장식이 가짜 단이 된다.

개발 중 저장했던 그림이 로컬에 있으면 `Output/diag/page_01_systems.png` 가 1페이지 단 상자다. git에는 PNG를 올리지 않았다. 다시 보려면 레이아웃 코드를 돌려 같은 이름으로 저장하면 된다.

## 세로줄

단 안에서 세로로 검은 선을 모아 마디 경계를 만든다. 음자리표·조표를 세로줄로 오인하지 않으려면 **왼쪽을 건너뛰고** 스캔한다. 1단은 너비의 약 24%부터.

실패하면 단을 마디 수로 똑같이 나눠 `bars_from_detect=False`. 감사는 이 경우 경고만 한다.

## 입출력

입력: 스티치된 PDF 그림(numpy), `page_y_positions`, dpi=200, `total_measures=90`  
출력: `ScoreLayout`

`system_for_measure(14)` → 그 마디가 그려진 단.

## 자주 하는 실수

1. 페이지마다 따로 좌표를 쓰고 스티치 y를 안 더한다. 2페이지부터 커서가 위로 점프한다.
2. dpi를 스티치와 검출에서 다르게 쓴다. 200으로 맞춰라.
3. 5줄 오선을 각각 단으로 본다.
