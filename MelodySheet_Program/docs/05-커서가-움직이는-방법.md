# 05. 커서가 움직이는 방법

한 시각 `t`(초)가 화면의 세로 막대가 되는 과정이다.

## 다섯 단계

1. **음원 앞 무음만 뺀다.** 다성 상관으로 오프셋을 구하지 않는다. 점수가 평탄해서 가짜 지연이 나온다.
2. **`timeline.measure_at(t)`** → 지금 마디, 마디 안 진행률 0~1.
3. **`layout.system_for_measure(마디번호)`** → 그 마디가 있는 단. 단의 `y0, y1`.
4. **가로 x**  
   단에서 그 마디의 왼쪽·오른쪽 세로줄 `left, right`를 얻는다.  
   마디 안 위치는 기보 길이 앵커 `x_frac_at(t)` (0~1).  
   `x = left + (right - left) * x_frac`
5. **세로 스크롤 y**  
   그 단이 화면 한가운데 오도록 `y_offset` 을 잡는다.  
   같은 페이지 아랫단은 마지막 마디의 **뒤 30%** 에서만 내린다.  
   **다음 페이지**는 마지막 마디가 거의 끝난 뒤, 최대 **0.4초** 만 스크롤한다. 그 전에 넘기면 “음을 다 듣기 전에 장이 바뀐다”.

## 식의 의미

`x_frac` 이 0이면 마디 왼쪽 세로줄, 1이면 오른쪽 세로줄.  
음머리 개수가 기보 발음 수와 같은 마디만 PDF x를 쓴다. 아니면 시간 선형이다. **8분/4분을 그림만 보고 나누지 않는다.**

## 함수 입출력

`SyncManager.calculate_sync(elapsed, img_w, img_h, viewport_h)`

- 입력: 본편 경과 초, 스티치(스케일 후) 크기, 화면 높이 1080
- 출력: `(y_offset, (cursor_x, cursor_y, width, height))`
- 커서 좌표는 **화면** 기준. 그릴 때 시트 왼쪽 여백 `x_offset` 을 더한다.
- 막대 폭 16, 색 BGR `(200, 211, 76)`, 투명도 0.55

`viewport_h` 는 1080, 헤더 42픽셀 아래부터 그린다.

## 직접 확인

영상을 기다리지 말고, 파이썬에서 한 시각만 찍어 볼 수 있다. 레이아웃까지 만들면 무겁다. 시계만으로도 “27.65초는 몇 마디인가”는 `inspect_timeline.py` 가 보여 준다.

페이지가 너무 일찍 넘어가면 `sync_manager.py` 의 `_scroll_offset` 과 감사 항목 “페이지 유지”를 본다. 마지막 마디의 80% 지점에서 y가 이미 다음 페이지면 FAIL이다.

## 자주 하는 실수

1. MIDI 온셋에 커서를 붙인다.
2. 페이지를 단 시간의 85%부터 미리 섞는다. 예전에 그렇게 했다가 고쳤다.
3. `y_offset` 을 페이지 번호 × 1080으로 둔다. 단 높이가 페이지마다 다르다.
